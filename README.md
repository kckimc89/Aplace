# 세계 명소대백과 Stage 1.4 — PHOTO LIBRARY

Stage 1.2 기준, 101개국 및 68개 명소 기본자료를 변경하지 않고 앱 전용 사진 누적 보관 기능을 추가했습니다.

부모모드 → 명소 카드 → 「사진 파일 추가」로 iPad 파일 앱의 사진 여러 장을 선택할 수 있습니다. 저장 시 긴 변 1600px JPEG 품질 0.8로 축소하고, 일반 Apple 사진 앱을 사용하지 않는 Safari/홈화면 앱의 IndexedDB에 이미지 자체를 보관합니다. 「다른 사진 찾아보기」에서 사진을 승인하면 다운로드(CORS 허용 시) 후 내부 저장합니다. 현재 화면에 보이는 외부사진은 「현재 사진 보관」으로 저장할 수 있습니다.

부모모드의 「전체 백업」은 앱 안에 누적된 이미지 바이너리를 포함한 JSON 파일을 생성합니다. 파일 앱에서 iCloud Drive/세계 명소대백과 같은 별도 폴더를 만든 뒤 보관하세요. iCloud 자동 연동이 아니며, 앱 내부 IndexedDB는 파일 앱에 노출되는 디렉터리가 아닙니다. Safari와 홈화면 앱은 저장 공간이 달라질 수 있으므로 이 백업파일을 통해 옮기세요.

주의: iPad 또는 Safari에서 IndexedDB가 정리되거나 앱이 삭제되면 사진이 소실될 수 있습니다. 백업이 유일한 안전장치이므로 첫 사진 몇 장을 등록하고 백업/복원을 반드시 시험하세요. 원본 외부사진 URL 및 위키미디어 검색 결과가 사라져도 내부 저장한 사진은 보입니다. 외부 원본 서버가 CORS 접근을 차단하면 이미지 저장이 실패할 수 있으므로 파일 앱을 통한 수동 등록을 사용하세요. 공개 배포 사진은 라이선스를 별도로 검토하세요.

검증: 소스 JS 문법/ZIP 구조와 1.2 데이터 일치 확인. 실물 iPad 및 외부 다운로드/복원은 아직 미검증. 전체 ZIP 파일을 *명소대백과* 저장소에 업로드하고 ?v=14-content-first로 새로고침하세요. 음식대백과 저장소에는 업로드하지 마세요.


## Stage 1.4 CONTENT FIRST
- 15개국 × 30/20곳 = 370곳 후보를 새로 정리했습니다.
- 기존 68개 명소, 기존 사진과 사진보관/복원 코드를 보존했습니다.
- 동일 국가에서 이름이 정확히 일치하는 기존 명소는 기존 ID/사진을 유지하고 설명만 새 초안으로 교체했습니다. 저장소의 사용자 수정 설명은 앱에서 우선 적용됩니다.
- 일부 기존 명소가 이번 370개 목록과 명칭이 다를 수 있어 삭제하지 않았습니다. 총 기본 명소 수는 370보다 많을 수 있습니다.
- 새로운 설명은 편집 초안으로서 항목별 위키데이터 ID·현지어 별칭·대표사진·출처 검증 전입니다. 사진 없는 명소에 사진을 지어 넣지 않았습니다.
- 이미 사파리에 저장된 부모 수정 데이터는 유지됩니다. 업로드 전에 백업하시길 권합니다.
