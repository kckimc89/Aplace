# 세계 명소대백과 Stage 1.6 — GROWING ENCYCLOPEDIA

## 기준과 실제 변경

- Stage 1.5 SEARCH & STORY 전체파일을 기준으로 작업했습니다.
- 15개국 기본 명소 374개, 101개국 목록, 기존 명소 ID와 원래 등록된 사진 정보를 유지합니다.
- 그중 기존 설명이 짧았던 **308개 명소**에 각각 장소별 역사·건축·자연·문화 사실을 담은 한국어 문단을 새로 작성해 보강했습니다. 기존 긴 설명 66개는 그대로 유지했습니다.
- 이 원고는 편집 초안으로, 374곳 전체에 대한 독립적인 문헌·현지어·라이선스 검증을 마쳤다는 뜻은 아닙니다. 나라별 검토는 계속 필요합니다.
- 사용자가 앱에서 수정한 설명은 여전히 기존 localStorage 키를 사용하고 우선 적용합니다. 사진은 동일 IndexedDB 이름/저장 구조를 사용하므로 기존 로컬 이미지를 보존합니다.
- 명소 카드의 부모모드에 `설명 덧붙이기`와 `선택 사진 삭제`를 추가했습니다. 등록 이미지는 기존처럼 1600px JPEG 압축, 해시가 지원되면 중복 이미지 파일 저장을 막습니다.
- 부모모드에 **이 기기 앱의 사진 장수 및 압축 용량**을 표시합니다.
- **사진 포함 전체 백업**은 파일명을 시각까지 포함하며, iCloud Drive → `세계 명소대백과` 폴더에 이용자가 직접 저장하도록 안내합니다. 자동 iCloud 접근이나 동기화는 불가능합니다.
- **백업 복원**은 기존 설명과 사진을 지우지 않는 합치기 방식으로 조정했습니다. 현재 앱에 있는 설명 편집내용을 우선 보존합니다.

## 설치와 시험

1. 이전 버전 앱에서 사진 포함 백업을 iCloud Drive에 만들어 보관합니다.
2. 현재 사용 중인 **명소대백과** GitHub Pages 저장소에 이 ZIP의 모든 파일을 업로드합니다. 음식대백과 저장소는 수정하지 않습니다.
3. Pages 배포 후 웹 주소 끝에 `?v=16-growing-library`를 붙입니다. 화면 표시 `Stage 1.6`인지 확인합니다.
4. 예를 들어 콜로세움, 자금성, 사그라다 파밀리아에서 카드 설명을 비교하고 사진 1장을 추가해 저장→재실행→백업까지 소량 시험합니다.
5. 백업 다운로드 파일을 파일 앱의 iCloud Drive / 세계 명소대백과 폴더에 직접 옮기고, 파일 앱에서 파일 크기를 확인합니다.

## 중요한 주의사항

- 실제 새 대표사진을 374개 명소에 자동으로 확보한 버전이 **아닙니다**. 후보사진 검색은 이전 버전처럼 온라인 연결이 필요하지만 선택해 앱에 저장한 이미지는 오프라인에도 남습니다(앱 내부 저장소가 유지될 때).
- iCloud의 폴더를 만들어도 앱 데이터가 자동 저장·동기화되지는 않습니다. Safari 웹사이트 데이터를 삭제하거나 홈화면 앱을 제거하면 사진 저장이 사라질 수 있으므로 백업이 필요합니다.
- 이미지 용량 통계는 현재 Safari 또는 홈화면 앱 **그 저장소에 저장된 사진만** 계산합니다.
- 앱 사진의 크롭·공개 사용 전 원본 출처·저작자·라이선스 조건을 반드시 확인해야 합니다.
- JS 문법·데이터 개수·ZIP 검사 등을 시행했습니다. **실제 iPad Safari의 파일 선택·사진 압축·백업 복원은 직접 검증하지 못했습니다.**
