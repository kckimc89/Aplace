# 세계 명소대백과 Stage 1.5 — SEARCH & STORY

## 이번 판에 실제 구현한 내용

- **기준 원본:** Stage 1.4 CONTENT FIRST (기본 명소 374개, 101개국 목록, 우선 15개국)
- **사진 검색:** 위키미디어 공용에서 다국어 이름 및 별칭, 명소와 연결된 사진 분류, 하위 분류(최대 12개), 정확한 Wikidata QID가 확인되면 사진의 ‘depicts(P180)’ 구조화된 태그를 함께 조회합니다.
- **초기 영어 이름이 없는 신규 명소:** 위키데이터에서 정확하게 일치하는 한국어 이름을 찾고 국가(P17) 정보를 대조한 뒤 영어·현지어 후보를 검색에만 사용합니다. 자동으로 부모가 확정한 명소 식별정보를 변경하지 않습니다.
- **후보사진 구분:** CC0, 퍼블릭 도메인, 저작자 정보가 있는 CC BY/CC BY-SA 등 기본 이용조건을 탐지하여 우선 표시합니다. 결과의 정확성·저작자·법적 조건까지 자동으로 보증하지는 않습니다. 불명확한 사진은 원본 사이트 링크로 확인합니다. 스크린샷/크롭을 해도 원래 저작권은 변하지 않습니다.
- **후보 사진 슬라이드쇼:** 라이선스 유형이 확인된 후보를 6.5초 간격으로 크게 보여주고 이전/다음/일시정지/원본 방문을 제공합니다. 검색 결과를 저장하지 않는 일회성 감상입니다.
- **사진 누적 저장:** 부모모드에서 개별 후보를 고르면 웹앱의 IndexedDB에 이미지 파일 및 출처정보를 함께 저장합니다. 메타데이터까지 별도로 로컬스토리지에 반복 쓰지 않아 이전의 저장오류 원인을 줄였습니다. 카드의 사진첩과 나라 여행에서 공유합니다. `사진 파일 추가`와 `대표사진 지정`도 지원합니다.
- **백업·복원:** 기존 사진 ID/기존 백업 포맷을 보존합니다. 새 사진의 출처·저작자·라이선스 정보를 사진 데이터와 함께 백업합니다. iCloud Drive로 저장하는 동작은 사용자가 직접 합니다.
- **카드 설명:** 전체 374개 명소는 유지. 그중 66곳을 역사·특징·의의 중심의 장문 설명으로 1차 보강했습니다. 나머지 308곳은 기존 초안을 그대로 둡니다. ‘명소_검토표.csv’에서 구분할 수 있습니다. 모든 항목의 개별 사실관계 검증은 아직 끝나지 않았습니다.

## 설치

1. 기존 명소대백과에서 **사진 포함 전체 백업**을 먼저 수행하고 iCloud Drive에 저장합니다.
2. 새 ZIP을 풀어 **ZIP 안에 있는 전체 파일**을 기존 명소대백과 GitHub 저장소의 기존 배포 파일과 교체합니다. 음식대백과 저장소는 건드리지 마세요.
3. GitHub Pages 배포 후 기존 URL에 `?v=15-search-story`를 붙여 열고 **Stage 1.5**를 확인합니다. 이 쿼리 문자열은 버전 표시가 아닌 브라우저 캐시 갱신용입니다.
4. 부모모드에서 자금성/콜로세움/사그라다 파밀리아 카드 → ‘다른 사진 찾아보기’ → ‘후보 사진 슬라이드쇼’ 또는 ‘사진첩에 저장’ 순서로 시험합니다.
5. **사진 1장 저장 → 카드 닫고 다시 열기 → Safari 완전 종료 후 재실행 → 백업 생성**을 먼저 시험한 후 사진을 늘리세요.

## 알려진 제한

- 외부 API의 연결/요청 제한, 일부 명소의 별칭 부족, 분류 자료 부족으로 명소마다 검색 결과 수가 다를 수 있습니다. 모든 명소에 사진이 많이 나오는 것은 보장되지 않습니다.
- 실제 iPad Safari에서 API 동작, IndexedDB 용량, 백업 후 사진 복원의 전 과정을 아직 직접 검증하지 못했습니다. 브라우저 모의응답을 이용해 검색 후보 표시·슬라이드쇼의 동작만 검증했습니다.
- 사진 이용조건 자동 표시는 참고용 필터이며 최종 법적 검증이 아닙니다. 부모는 명소 일치·원본 저작자·라이선스·변경표시를 확인해야 합니다. 공개 GitHub에 이미지 파일을 추가하려면 해당 배포 라이선스를 따로 확인해야 합니다.
- 확정 사진을 앱 내부에 저장한 경우에도 기기 저장소 삭제나 홈화면 앱 재설치 시 사진이 소실될 수 있습니다. **iCloud Drive 사진 포함 백업은 필수**입니다.
